# AI Team 实施路线与验收

阶段按验收门槛推进，不依赖展示动画或模型自报完成。

| 阶段 | 可交付成果 | 验收标准 | 当前范围 |
|---|---|---|---|
| P0 · 产品与协议 | DSH 式三栏工作台、七个独立线程、三层事实 | 主控、一级、二级可区分；二级保留同组与父线程；明确显示模拟边界 | V1 |
| P1 · 层级模拟 | 24 步脚本、播放/暂停/单步、拓扑、事件、产物与验收 | 父线程不能先于子线程完成；未知送达停止；对账保留原 requestId；验收需要三项证据 | V1 |
| P2 · 发布 | 公开静态网页、开源仓库、测试与复现说明 | 匿名访问能加载 CSS/JS；交互跑通；源码提交与部署对应；无凭据或本机状态进入发布包 | V1 |
| P3 · 一条真实链路 | 本地控制面接入 DSH Web 的 Agent Call 桥 | 专用会话可打开；真实 requestId 送达；原生终态与产物经调用方核验；不确定送达不重发 | 待真实联调 |
| P4 · 层级执行与持久化 | LangGraph 顶层图、SQLite 审计投影、持久化 dispatch claim、租约 | 进程中断后从检查点恢复；并发不会重复派发；分支回收后才能汇总；人工验收可暂停和恢复 | 后续 |
| P5 · 可选多运行时 | Grok/Antigravity 与 MAF worker 适配 | 每条路线有独立原生可见性和结果证据；MAF 节点映射到同一协议，不拥有第二套顶层重试权威 | 后续 |

P3 优先复用现有 `dsh-web/bridge.mjs`，再连接统一 `send / status / collect` 契约。无需先把 DSH 整个运行时嵌入新项目。P4 引入 LangGraph 时，由它负责流程恢复；Agent Call 只负责受控通信；DSH 负责原生 DeepSeek 会话与工具执行。

V1 的简历可描述能力：

> 基于 Agent Call 协议和 DSH 会话交互构建多模型协作工作台，实现三级线程模拟、确定性事件回放、未知送达对账、父子结果回收与证据验收；提供公开交互演示和可复现自动化测试。

真实接入尚未通过 P3 时，不描述为已经部署真实多模型生产集群。
